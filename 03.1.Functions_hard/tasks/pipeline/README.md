## PIPELINE

`closure` `composition` `higher-order functions` `recursion limit`

### Условие

Та же идея, что и в задаче `make_adder` — цепочка
вызовов, которая копит состояние в замыканиях, а завершается вызовом
без аргументов, — только здесь копится не сумма, а **композиция
функций**.

Функция `pipeline(f)` возвращает функцию `add`:

* `add(g)`, где `g` — функция одного аргумента: возвращает **новую**
  функцию того же вида ("продолжение конвейера"), в которой `g`
  добавлена в конец цепочки;
* `add()` — без аргументов: завершает цепочку и возвращает готовую
  функцию одного аргумента — композицию всех функций, переданных
  в `pipeline` и во все `add`, в том порядке, в котором их добавляли.

Контракт: каждая функция в цепочке принимает **ровно один** аргумент
и возвращает одно значение — оно становится аргументом следующей
функции в цепочке.

### Пример

```python
p = pipeline(lambda x: x + 1)(lambda x: x * 2)(lambda x: x - 3)()
p(5)    # 9   -> ((5 + 1) * 2) - 3

only_one = pipeline(lambda x: x * x)()
only_one(4)   # 16 - цепочка из одной функции тоже работает
```

### Независимость цепочек

Как и в `make_adder`, каждый вызов `add(g)` возвращает **новое**
продолжение, не изменяя то, из которого он был вызван. Значит, из
одной и той же промежуточной точки можно построить несколько разных
завершённых конвейеров, и они не должны друг другу мешать:

```python
base = pipeline(lambda x: x + 1)(lambda x: x * 2)   # ещё не завершён

p_a = base(lambda x: x - 1)()
p_b = base(lambda x: x + 100)()

p_a(5)   # ((5+1)*2) - 1   = 11
p_b(5)   # ((5+1)*2) + 100 = 112
```

### Масштабируемость

Критически важно, чтобы создание конвейера масштабировалось на большое
число функций (в тестах — миллион шагов). Логично предположить, что и вычисление
должно масштабироваться аналогичным образом.

Однако здесь возникает проблема: для обеспечения независимости цепочек
необходимо избегать хранения изменяемого состояния в замыкании.

Данная проблема решается через создание рекурсивно разворачиваемой
«матрёшки» вызовов. Рекурсивное создание такой структуры возможно,
но её вычисление будет рекурсивным по своей природе.

Отказ от рекурсии затруднителен, поскольку «матрёшка» инкапсулирует
композицию функций. Альтернативой является хранение списка лямбда-функций.

Возможно использование immutable-списка в качестве состояния, что
обеспечит независимость веток цепочек. Однако это выходит за рамки
тематики домашнего задания.

В связи с этим ограничимся частичным требованием — масштабируемость
при **создании** конвейера. Списки для хранения функций использовать нельзя.
